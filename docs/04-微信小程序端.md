# 微信小程序端使用与开发说明

> 小程序端位于 `miniprogram/`，是一个**原生微信小程序**项目（不依赖 Taro / uni-app），
> 直接复用现有 Spring Boot 后端的 `/api` 接口、JWT 登录与静态图片 / 音频资源。
> 登录沿用后端的「账号密码 + JWT」，没有接入微信开放平台登录，因此不需要 `wx.login` / `openid`。
> 本文件说明怎么跑起来、页面与 Web 端如何对应、以及和 Web 端有哪些差异。

## 二、快速开始

### 1. 先启动后端

按根目录 README 的「快速开始」启动后端（MySQL + `mvn package` + `java -jar`），确认：

- <http://localhost:8080/api/home> 返回 `{"code":200,...}`
- <http://localhost:8080/images/album/a1.png> 能打开图片
- <http://localhost:8080/audio/track-1.wav> 能播放音频

小程序没有 Vite 代理，**所有请求直连后端地址**，所以后端必须先启动。

### 2. 用微信开发者工具导入项目

1. 打开「微信开发者工具」→ 导入项目；
2. 目录选择仓库里的 **`miniprogram/`**（注意不是仓库根目录）；
3. AppID 选择「测试号」即可（`project.config.json` 里默认 `touristappid`）；
4. 打开「详情 → 本地设置」，勾选 **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**；
5. 点击编译，首页应能看到轮播图与推荐歌单。

> `project.config.json` 已设置 `"urlCheck": false`，正常情况下第 4 步会自动生效；
> 如果仍报「不在以下 request 合法域名列表中」，手动勾选一次即可。

### 3. 配置后端地址

- 开发者工具在本机运行：默认 `http://localhost:8080` 就能用；
- 真机预览 / 后端在另一台电脑：进入小程序 **我的 → 设置 → 服务器地址**，
  填写电脑的局域网地址（如 `http://192.168.1.10:8080`），点「保存并测试连接」；
- 手机与电脑需在同一 Wi-Fi，且 Windows 防火墙放行 8080 端口。

地址保存在小程序本地缓存，随时可改，也可以「恢复默认地址」。

## 四、实现要点

### 1. 接口层完全复用

`utils/api.js` 里的方法与 Web 端 `frontend/src/api/index.js` 一一对应，路径相同（不带 `/api` 前缀，由 `request.js` 补全）。
后端统一响应 `{ code, message, data }` 的处理方式也一致：

- `code === 200`：解包 `data`；
- `code === 401`：清除本地 token，广播 `unauthorized`，由 `app.js` 提示并按需跳转登录；
- 其它：`wx.showToast` 提示 `message`，Promise reject。

### 2. 媒体地址自动补全

后端返回的封面、头像、音频都是相对路径（`/images/...`、`/audio/...`）。
`request.js` 在解包后递归处理 `cover / avatar / creatorAvatar / imageUrl / audioUrl` 字段，
统一补成 `服务器地址 + 路径`；缺图时回落到小程序内置的默认封面 / 头像。
因此 WXML 里直接 `src="{{item.cover}}"` 即可。

反过来，小程序后台编辑歌曲 / 个人资料时用 `toRelative()` 把本机地址还原成相对路径再提交，
避免把 `http://192.168.x.x:8080` 写进数据库。

### 3. 状态管理

小程序没有 Pinia，`store/user.js` 与 `store/player.js` 用「模块单例 + 发布订阅」实现：

- `userStore.subscribe(fn)`：登录 / 退出 / 资料更新时通知页面；
- `player.subscribe(fn)`：换歌、播放暂停、进度变化时通知页面；
- 页面的当前歌曲高亮由 `utils/page-player.js` 统一处理，页面只需在 `onShow` / `onHide` 调用 `attach` / `detach`。

### 4. 播放器

- 使用 `wx.createInnerAudioContext()`，`app.json` 声明 `requiredBackgroundModes: ["audio"]`，
  支持切后台继续播放（iOS 真机建议实测）；
- 队列、上一首 / 下一首、列表循环 / 单曲循环 / 随机、进度拖动、上报播放量与播放历史，
  行为与 Web 端 `stores/player.js` 一致；
- 播放条固定在页面底部（原生 tabBar 之上），每个页面引入一次 `<player-bar />`，
  组件内部通过 `pageLifetimes.show/hide` 控制订阅，避免后台页面持续 `setData`；
- 播放模式持久化在本地缓存，重新进入小程序后保留。

### 5. 歌词与格式化

- `utils/format.wxs` 提供 WXML 里可直接调用的 `fmt.count / fmt.duration / fmt.date / fmt.index`；
- 歌词解析在 `utils/format.js` 的 `parseLyric`，页面用固定行高 + `scroll-top`（px）实现高亮滚动，
  点击歌词可跳转到对应时间。

## 五、与 Web 端的差异

| 项目 | Web 端 | 小程序端 |
| --- | --- | --- |
| 运行环境 | 浏览器 + Vite 代理 | 微信内，直连后端 |
| 主题 | 浅色 / 深色可切换 | 仅浅色（跟随红色品牌色） |
| 播放器 | `<audio>` + 底部播放条 | `InnerAudioContext` + 迷你播放条 + 独立播放页 |
| 音量 | 播放条上的音量滑块 | 由系统音量控制 |
| 管理后台 | 全量 CRUD | 数据看板 + 用户管理 + 歌曲管理；其余建议用 Web 后台 |
| 列表交互 | 双击播放、悬停删除 | 点击播放、长按删除 / 取消收藏 |
| 登录 | 弹窗 | 独立登录页，支持登录后回跳（`redirect` 参数） |
| 搜索历史 | localStorage | `wx.setStorageSync` |

## 六、真机与发布注意事项

1. **必须 HTTPS**：正式环境的小程序只能请求已配置的 https 域名。
2. **配置服务器域名**：微信公众平台 → 开发管理 → 服务器域名，把后端域名加入
   `request 合法域名`（接口）、`downloadFile 合法域名`（图片 / 音频）。
3. **开发阶段**：在开发者工具关闭域名校验；真机调试可在「开发调试」中打开调试模式后临时跳过校验，
   但正式体验版必须配置域名。
4. **音频**：建议使用 https 地址与 mp3 / m4a 等通用格式；当前演示音频是 38～60 秒的 WAV 片段。
5. **图片**：与音频相同，来自后端 `/images`，需要保证域名可访问且已加入白名单。
6. **AppID**：`project.config.json` 使用 `touristappid` 方便导入；正式上传前替换成自己的 AppID。
7. **隐私协议**：若后续接入微信登录、相册等能力，需要在公众平台补充隐私保护指引。

## 七、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 首页一直空白，提示「网络异常，请检查服务器地址」 | 后端未启动、端口不是 8080，或开发者工具未关闭域名校验 |
| 真机请求失败，开发者工具正常 | 手机连的是 `localhost`，改成电脑局域网 IP，并放行防火墙 8080 |
| 图片全部不显示 | 检查「设置 → 服务器地址」；确认后端 `/images/**` 可访问 |
| 音频无法播放 | 真机要求 https；检查音频地址与格式；确认手机未静音（已设置 `obeyMuteSwitch = false`） |
| 登录后过一段时间提示登录失效 | JWT 默认 7 天过期，重新登录即可 |
| 看不到「后台管理」入口 | 只有 `role = 1` 的账号可见，使用 `admin / 123456` |
| 修改服务器地址后数据没变 | 返回上一页再进入，或下拉刷新；新地址在下次请求时生效 |
| 小程序切后台后音乐停止 | 确认 `app.json` 的 `requiredBackgroundModes` 未被移除；部分安卓机型需在系统设置中允许后台运行 |

## 八、开发与校验工具

小程序无法在命令行中完整运行，仓库提供了三个辅助脚本：

```bash
# 重新生成 tabBar 图标与默认封面 / 头像 / 轮播图
python tools/gen_mp_assets.py

# 静态检查：JSON、页面/组件文件、usingComponents、WXML 闭合、事件函数是否存在
python tools/validate_mp.py

# 逻辑冒烟测试：用 Node 模拟 wx 对象，验证请求封装、登录态、播放器、歌词解析等
node tools/mp_smoke_test.mjs
```

修改小程序代码后建议至少执行后两个命令，能覆盖大部分低级错误。

## 九、已知限制

- 管理后台只迁移了数据看板、用户管理与歌曲维护；歌手 / 专辑 / 歌单 / 轮播图的完整维护仍以 Web 后台为主。
- 没有实现深色模式、歌词分享、歌曲下载等功能。
- 播放器使用内置音频上下文，未接入微信「音乐」类目或第三方版权曲库。
- 演示音频为程序合成的 WAV 片段，仅用于功能演示。
