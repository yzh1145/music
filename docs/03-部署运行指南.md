# 换一台电脑如何启动（部署运行指南）

本文档面向「把项目拷到另一台电脑上跑起来」的场景，Windows / macOS / Linux 通用，命令以 Windows + PowerShell 为主，其它系统给出等价命令。

## 一、先装好这四样东西

| 软件 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | 17 及以上（推荐 17 或 21） | 后端用 Java 17 编译，Spring Boot 3.5 最低要求 17 |
| Maven | 3.8+ | 只在需要现场构建 jar 时用到；直接拿打包好的 jar 可以不装 |
| MySQL | 8.0 | 需要能创建库和表，字符集 utf8mb4 |
| Node.js | 20.19+ 或 22.12+ | Vite 7 的最低要求；npm 随 Node 一起装好 |

检查版本：

```powershell
java -version
mvn -v
node -v
npm -v
mysql --version
```

> 只装 JRE 不行，构建需要 JDK；`java -version` 能看到 17+ 即可。
> 如果装了多个 JDK，构建前设置 `JAVA_HOME` 指向 17+ 的那个目录。

## 二、拷贝哪些文件

整个 `music/` 目录拷过去即可，但下面这些「本机产物」不用拷，能省几百 MB 且避免换机后路径失效：

```
不用拷： frontend/node_modules、frontend/dist、backend/target、
         .tmp、.npm-cache
必须拷： backend/src、backend/pom.xml、frontend/src、frontend/package.json、
         frontend/package-lock.json、frontend/vite.config.js、frontend/index.html、
         sql/music.sql、docs、tools、README.md
可选：   backend/target/music-1.0.0.jar（拷了就不用在新机器上构建后端）
```

图片和试听音频都在 `backend/src/main/resources/static/` 里（约 15 MB），会跟着源码一起走，也会被打进 jar。

## 三、第一步：导入数据库

```powershell
mysql -uroot -p你的密码 --default-character-set=utf8mb4 < sql/music.sql
```

脚本会先 `DROP DATABASE IF EXISTS music_db` 再重建，重复执行不会冲突。

**数据库密码不是 123456 怎么办？** 不用改代码，启动后端时用环境变量覆盖即可（见下一节）。也可以直接改 `backend/src/main/resources/application.yml` 里的默认值。

## 四、第二步：启动后端（8080）

### 方式 A：拷了 jar，直接跑（最快）

```powershell
java -jar backend\target\music-1.0.0.jar
```

### 方式 B：在新机器上构建再跑

```powershell
cd backend
mvn -DskipTests package
java -jar target\music-1.0.0.jar
```

首次构建会联网下载依赖，需要几分钟；国内网络慢可以在 `~/.m2/settings.xml` 里配阿里云镜像。
本项目开发机是离线环境，所以之前用的是 `mvn -o`（离线）；**换到联网环境请去掉 `-o`**。

### 用环境变量适配新机器

配置文件里的连接信息都已写成 `${变量:默认值}` 形式，改环境变量即可，不必改代码、不必重新打包：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SERVER_PORT` | `8080` | 后端端口 |
| `DB_HOST` | `localhost` | MySQL 地址 |
| `DB_PORT` | `3306` | MySQL 端口 |
| `DB_NAME` | `music_db` | 数据库名 |
| `DB_USERNAME` | `root` | 数据库账号 |
| `DB_PASSWORD` | `123456` | 数据库密码 |
| `JWT_SECRET` | 内置演示密钥 | 生产环境请换成自己的随机串 |
| `JWT_EXPIRE_DAYS` | `7` | 登录有效期（天） |

PowerShell 示例（密码是 `abc123`、端口用 8080）：

```powershell
$env:DB_PASSWORD='abc123'
java -jar backend\target\music-1.0.0.jar
```

cmd 示例：

```bat
set DB_PASSWORD=abc123
java -jar backend\target\music-1.0.0.jar
```

macOS / Linux 示例：

```bash
DB_PASSWORD=abc123 java -jar backend/target/music-1.0.0.jar
```

启动成功的标志是日志里出现 `Started MusicApplication in ... seconds` 和 `Tomcat started on port 8080`。
验证：浏览器打开 <http://localhost:8080/api/home>，能看到 `{"code":200,...}` 的 JSON 就说明后端和数据库都通了；<http://localhost:8080/images/album/a1.png> 能出图说明静态资源正常。

## 五、第三步：启动前端（5173）

```powershell
cd frontend
npm install
npm run dev
```

打开 <http://localhost:5173>，用 `admin / 123456`（管理员）或 `test / 123456` 登录。

- `npm install` 国内慢可先切镜像：`npm config set registry https://registry.npmmirror.com`
- 如果后端不在本机或端口不是 8080，用环境变量指定代理目标：
  ```powershell
  $env:API_TARGET='http://192.168.1.10:8080'
  npm run dev
  ```
- 想改前端端口：`$env:FRONTEND_PORT='8081'; npm run dev`
- 想让同一局域网的手机/同事访问：`npm run dev -- --host`，然后用 `http://你的内网IP:5173` 打开（注意 Windows 防火墙放行 5173）。

### 前端的生产构建

```powershell
cd frontend
npm run build      # 产物在 frontend/dist
npm run preview    # 本地预览构建产物
```

## 六、一键启动脚本（Windows）

项目根目录提供了两个脚本，双击或在终端运行即可：

| 脚本 | 作用 |
| --- | --- |
| `start-backend.cmd` | 进入 backend，jar 不存在时先 `mvn -DskipTests package`，再 `java -jar` 启动 |
| `start-frontend.cmd` | 进入 frontend，`node_modules` 不存在时先 `npm install`，再 `npm run dev` |

两个脚本都会读取上面那些环境变量，所以换机器时可以先 `set DB_PASSWORD=...` 再运行。

## 七、正式部署（可选）

1. 后端打包成 jar，在服务器上以 systemd / 计划任务方式常驻（`java -jar music-1.0.0.jar`）。
2. 前端 `npm run build` 后把 `dist/` 交给 Nginx，并反代接口与静态资源：

```nginx
server {
    listen 80;
    server_name music.example.com;

    root /var/www/music/dist;
    index index.html;

    # Vue Router history 模式必须回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 图片与音频也可以继续由后端提供
    location /images/ { proxy_pass http://127.0.0.1:8080; }
    location /audio/  { proxy_pass http://127.0.0.1:8080; }
}
```

3. 生产环境务必通过环境变量设置 `DB_PASSWORD` 和 `JWT_SECRET`，不要把真实密码写进仓库。

## 八、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `java -jar` 报 `UnsupportedClassVersionError` | JDK 低于 17，换 17+ 的 JDK 或把 `JAVA_HOME` 指过去 |
| `mvn` 报 `The JAVA_HOME environment variable is not defined correctly` | 没配 `JAVA_HOME`，设为 JDK 安装目录（不是 bin 目录） |
| 后端启动报 `Access denied for user 'root'@'localhost'` | 数据库密码不对，用 `DB_PASSWORD` 覆盖或改 yml |
| 报 `Unknown database 'music_db'` | 还没导入 `sql/music.sql` |
| 中文变成乱码 | 导入时加 `--default-character-set=utf8mb4`；确认库表是 utf8mb4 |
| 前端 `npm install` 报 `EBADENGINE` | Node 版本太低，Vite 7 需要 20.19+ / 22.12+ |
| 前端能打开但接口 500 / 转圈 | 后端没起或端口不一致，检查 `API_TARGET`；看浏览器 Network 里 `/api/*` 的返回 |
| 端口被占用 | 后端用 `SERVER_PORT` 改端口，前端用 `FRONTEND_PORT`，同时改 `API_TARGET` |
| 登录后刷新掉线 | 检查 localStorage 是否被清理；JWT 有效期默认 7 天 |
| 浏览器提示跨域 | 开发时走 Vite 代理不会有跨域；若前端直连 8080，需要后端 `CORS` 允许该来源 |
| 在受限沙箱里 `npm run build` 报 `spawn EPERM` 或临时文件删除失败 | esbuild 需要启动子进程、需要可写临时目录：放开权限并把 `TEMP` 指向工作区目录（普通电脑不会遇到） |
